# AI Video Platform

Upload videos directly to a private S3 bucket, process them asynchronously (thumbnail + Whisper transcript), store transcript chunks in a PostgreSQL + pgvector database, and enable semantic search over video transcripts.

## Features
- **Direct-to-S3 uploads** using **FastAPI-generated presigned PUT URLs**
- **Asynchronous processing** with **Celery + Redis**
- **Thumbnail generation** using **FFmpeg**
- **Speech-to-text transcription** using **OpenAI Whisper**
- **Transcript chunking + embeddings** stored in **Postgres (pgvector)**
- **Semantic search** endpoint over transcript embeddings
- **Secure playback** using **temporary presigned GET URLs**
- Dockerized multi-container local development setup

---

## Tech Stack
- **Frontend:** React + Vite (runs in Docker)
- **API:** FastAPI (Python)
- **Async workers:** Celery Worker (Python)
- **Database:** PostgreSQL 15 + **pgvector**
- **Message broker:** Redis
- **Storage:** AWS S3 (private bucket; access via presigned URLs)
- **Media processing:** FFmpeg
- **Transcription:** Whisper (openai-whisper)
- **Embeddings:** See `backend/embeddings.py` (OpenAI embeddings + pgvector)

```mermaid

    BE->>DB: Create Video row (status="uploaded")

    Celery->>DB: status="processing"

    Celery->>S3: Download video file
    Celery->>Celery: Generate thumbnail (FFmpeg)
    Celery->>S3: Upload thumbnail

    Celery->>Celery: Transcribe audio (Whisper)
    Celery->>DB: Save transcript + thumbnail_path

    Celery->>Celery: chunk transcript
    Celery->>Celery: embed chunks (OpenAI embeddings)
    Celery->>DB: Store chunks in VideoChunk (pgvector)

    Celery->>DB: status="done"

    User->>FE: Run semantic search
    FE->>BE: GET /search?q=...
    BE->>DB: Vector similarity search over VideoChunk.embedding
    BE-->>FE: Return results + presigned thumbnail URLs
```

## Backend API

Base URL: `http://localhost:8000` (when running with Docker Compose).

### Upload
- `POST /videos/presigned-url`
  - **Request:** `{ "filename": string, "content_type": string }`
  - **Response:** `{ "url": string, "key": string }` (presigned PUT URL)

- `POST /videos/confirm`
  - **Request:** `{ "filename": string, "s3_key": string }`
  - **Response:** `{ "id": number, "status": string }`
  - **Behavior:** creates a `Video` row and enqueues `process_video(video_id, s3_key)`.

### Video browsing / playback
- `GET /videos`
- `GET /videos/{video_id}`
  - Returns `filepath` as a **temporary presigned GET URL** (used for secure playback).

### Delete
- `DELETE /videos/{video_id}`
  - Deletes the DB record and deletes the corresponding S3 objects (video + thumbnail).

### Semantic search
- `GET /search?q=...&limit=10`
  - Uses pgvector cosine distance on embedded transcript chunks.

### Health
- `GET /health`
- `GET /redis-health` (debug)

## Environment variables

The project uses a root `.env` file (loaded by both backend and worker, and wired into `docker-compose.yml`).

Populate at least:
- `AWS_REGION`
- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`
- `S3_BUCKET_NAME`
- `DATABASE_URL`
- `REDIS_URL`
- `OPENAI_API_KEY`

> Do not commit real secrets. Consider adding `.env.example`.

## How to make a good architecture diagram (practical checklist)

1. **Start with the boundaries**: Client / API / Worker / Data stores / External services (S3).
2. **Show security boundaries**: mark S3 as *private* and show *presigned URLs* as the only access method.
3. **Choose one primary diagram purpose**:
   - request/task flow (use boxes + arrows or sequence diagrams)
   - data model flow (separate diagram if needed)
4. **Use labels for protocols**: label endpoints like `POST /videos/confirm`, `presigned PUT`, `process_video.delay`.
5. **Keep it readable**: avoid tiny text and too many nodes; consistent naming and consistent arrow directions.
6. **Use Mermaid for GitHub**: `graph TD/LR` and `sequenceDiagram` are ideal for this stack.

## Troubleshooting
- **Celery tasks don’t run**: check `REDIS_URL` and Redis container health.
- **Videos stuck in processing**: check worker logs; failures are marked as `status="error"`.
- **Search returns no results**: confirm embeddings were generated and stored in `video_chunks`.
- **Video playback fails**: verify S3 bucket permissions used to generate presigned GET URLs.
